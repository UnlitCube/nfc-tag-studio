## 監査で分かった「不安定さ」の正体（要約）

ハードの揺れより、main の状態管理と画面の作りの欠陥でほぼ説明できた（監査役が偽の PC/SC で本物の NfcService を動かして再現）。

1. **識別がどのリーダーのイベントでも走り、1 つしかない `card` を上書きする**。開発 PC の並びは [FS USB Token 0, PaSoRi, YubiKey]。起動時に YubiKey の識別失敗が PaSoRi のタグ情報を消し、トークンには FF CA が自動で飛ぶ（I6 違反）。
2. **識別に 1 回失敗すると再試行しない**。置いたままでも「タグなし」で、読み取りボタンが押せず詰む。
3. **読み取り中にタグが離れても NTAG は「成功」で返り**、0 埋めの像が文書になる（「パスワードが必要な領域」と誤った理由つき）。
4. **仮想リーダーが有効だと、画面は実機のタグを出すのに、読み書きは仮想タグに行く**。
5. **バイナリ編集は「いま載っているタグ」に、「読んだタグ」との差分を書く**。別のタグに載せ替えると、警告なしに混ざった内容を書く。ファイル・新規の文書は、ファイル自身との差分（＝何も書かない）。
6. **未書き込みの編集が、再読み取り・別画面の読み取り・ファイルを開く・NDEF の書き込み・窓を閉じるで、確認なしに消える**。書き込みの一部失敗でも、再読み取りで編集が消える。
7. NDEF 編集はタグの既存のレコードを読み込まずに空から始まり、そのまま書くと既存を消す。バックアップは同じタグへ戻せない。ホームの「ファイルを開く」は選んだファイルを捨てる。
8. 一括発行: 1 枚ごとの結果が即座に「離してください」で上書きされる・途中で離すと次のタグに同じ番号・停止→再開で最初から・開始の瞬間に置いたままのタグへ確認なしで書く。

## 決めたこと（覆せる）

| # | 決定 | 理由 / 代案 |
|---|---|---|
| D1 | 選んだリーダーが未接続なら、黙って他へ切り替えない（`activeReason: 'selected-missing'`、画面で「自動選択に戻す」） | 利用者が明示で選んだものを黙って変えない。代案: 自動選択へ落とす |
| D2 | 自動読み取り（`settings.autoRead`、既定オン）。ホーム・バイナリ編集・NDEF 編集だけ。未書き込みの変更がある文書と、ファイル・新規の文書は自動で置き換えない | 「置いたのに何も起きない」を無くす。バックアップの 2 枚の流れ・ファイルからの書き込みを壊さない |
| D3 | 画面の keep-alive（一度開いた画面は描画したまま隠す） | 画面を移る・ヘルプを開くだけで作業中の状態が消えていた。代案: 画面ごとの下書きを store に移す |
| D4 | 未書き込みの変更の確認は 2 択（破棄して続ける / キャンセル） | 3 択（保存してから）は確認の部品の拡張が要る。キャンセルして保存すればよい |
| D5 | 別のタグ・ファイル・新規の文書を書くときは、書く直前に書き込み先を読み、その内容との差分で計画し、「別のタグへ書き込みます（複製）」と書き込み先を確認に出す | 混ざった内容の書き込みと「何も書かない」を同時に解く |
| D6 | 一括発行の効果音は store が鳴らす | keep-alive で画面が隠れていても鳴る。二重を防ぐ |
| D7 | 用語: 読み取る（ファイルは「開く」）/ タグに書き込む・ファイルに保存 / タグ / 置く・離す / 未書き込みの変更 / 画面に「単位」を出さない / ボタンは動詞 | 呼び名の揺れ（読み込む・かざす・外す・カード）が監査で多数 |
| D8 | `NFCTS_NO_PCSC=1`（パッケージ版では無視）で PC/SC を起動しない | E2E が実機のタグに触れないことを構造で保証する |
| D9 | 自動読み取りは公開の標準鍵（組み込みの 3 本）だけで読む。手動の［読み取る］は登録した全部の鍵を試す。読めないセクタが出たら［登録した鍵で読み取る］ | 置くだけで、偽装カードに運用者の鍵の認証を試させない（mfkey32 で鍵を割り出される経路。レビュー R-UX-4）。全部を標準鍵だけにすると、運用者の鍵のカードがホームで読めない（FLOW-2）に戻る |
| D10 | NFC リーダーと判定できない機器は、設定で選べるまま残し、ラベルと warn の確認で知らせる | 判定は名前の推定なので、未知の本物の NFC リーダーの逃げ道を残す（R-UX-7） |
| D11 | ストレージ方式（PaSoRi など）では NTAG のパスワード欄を無効にして理由を出す。main はパスワードを黙って飛ばさず `READER_NO_AUTH`。一括発行のパスワード保護は語の入力つきの強い確認 | PaSoRi は PWD_AUTH を送れない。保護したタグを後から読み書きできなくなる（R-UX-1） |
| D12 | 英語の「未書き込みの変更」は "Unsaved changes" にそろえる | 画面ごとに "Unwritten" と "Unsaved" が混在していた |
| D13 | 書き込みの結果は LastWriteCallout が残すので、書き込みの成功トーストは出さない。トーストは主ボタンに重ねず、確認ダイアログの間は奥へ。同じ内容はまとめる。「処理中」の帯は確定してから | 読み取り直後のトーストが「タグに書き込む」を約 4.5 秒覆い、押しても反応しなかった（E2E で 0.5 秒ごとに実測） |
