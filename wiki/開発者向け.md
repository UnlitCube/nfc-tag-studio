# 開発者向け

ソースからのビルド・テスト・リリースの流れです。参加の手順は [CONTRIBUTING.md](https://github.com/UnlitCube/nfc-tag-studio/blob/master/CONTRIBUTING.md)、設計の正典は [docs/DESIGN.md](https://github.com/UnlitCube/nfc-tag-studio/blob/master/docs/DESIGN.md) にあります。

## 必要なもの

- Windows 10 / 11（PC/SC の実機の経路は Windows で作っています。単体テストとビルドは Linux でも通ります）
- Node.js 22.12 以上（配布物は `.node-version` の版で作ります）
- Git

## ビルドと起動

```bash
npm ci             # 依存の導入（Electron 本体の取得も自動）
npm run dev        # 開発起動（start-dev.bat をダブルクリックでも可）
npm run build      # out/ にビルド
npm run dist:win   # release/ に portable の exe と zip を作る
```

## 検査

| コマンド | 中身 |
|---|---|
| `npm test` | 型検査 + 単体テスト（vitest）+ ロジックのスモーク |
| `npm run e2e` | Playwright で画面の流れを通す（仮想リーダーだけ。実機のリーダーには触れない） |
| `npm run notices:check` | 同梱する第三者のライセンスの通知（`THIRD_PARTY_NOTICES.txt`）が最新か |
| `npm run docs:check` | 文書のリンクと、個人の環境の値が無いこと |
| `npm run site:build` | GitHub Pages のサイトを `site-dist/` に作る |
| `npm run shots` | README・Wiki・Pages の画面のキャプチャを `docs/images/` に撮り直す |

`npx vitest` を直接叩かず、`npm run unit` を使ってください（カレントディレクトリのドライブ文字が小文字だと vitest が二重に読み込まれる罠があり、`scripts/run-vitest.cjs` が避けます）。

## 実機での書き込みの確認

`npm run hw:write` は、**捨ててよいタグ**にだけ使う、実機での書き込みの確認です。そのタグの UID を `NFCTS_HW_WRITE_UID` に入れたときだけ動き、UID が違えば何も書かずに止まります。書くのはユーザー領域だけで、最後に元の内容へ戻します。CI では流しません。

## CI とリリース

| ワークフロー | いつ | 中身 |
|---|---|---|
| `ci.yml` | master への push・PR | 型検査・単体・スモーク・ビルド・通知・CHANGELOG・文書・サイト（Linux） |
| `release.yml` | `v*` のタグ・手動 | 上の検査 → Windows で E2E・パッケージ・中身の確認・起動の確認 → Release（手動のときは作らない） |
| `pages.yml` | `site/` などの変更・Release の後・手動 | GitHub Pages を公開 |
| `wiki.yml` | `wiki/` の変更・手動 | この Wiki に `wiki/` を写す |

リリースの手順は [docs/RELEASING.md](https://github.com/UnlitCube/nfc-tag-studio/blob/master/docs/RELEASING.md) にあります。

## 守ること

- UID の書き換え・magic card のバックドア・鍵の解析は実装しません（[[安全の約束]]）。
- 画面の文言は `src/renderer/src/i18n/` に日本語と英語を同時に足します（型で過不足が落ちます）。
- 鍵・パスワードをログ・エラーの詳細・台帳・ダンプに入れません。
